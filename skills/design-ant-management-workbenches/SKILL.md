# Ant Design 管理工作台体验

## 工作方式

- 先理解任务、数据规模、接口契约和现有交互，再选择 Ant Design 组件与行为；不要脱离场景机械套用规则。
- 以交互体验为主；仅当 Ant Design 默认行为会破坏规则时，记录必要的组件选择、关键选择器和覆盖约束。沿用项目主题和语义 token，不固定具体色值或 CSS 架构。
- 仅在用户明确要求“提炼”“沉淀”或“更新 skill”时修改本 skill。更新前通读已有规则，合并重复内容，替换矛盾或过时规则，删除失效内容；不要只追加。

## 信息展示

默认优先展示用户理解并用于当前任务的业务信息。不要仅因接口返回了数据库主键、内部 ID、技术编码或枚举原值，就主动将其放入表格、卡片、详情或辅助文案；用户未明确要求时，仅将其用于组件 key、请求参数等内部逻辑。只有需求明确要求，或既有业务规则已将其定义为用户识别、检索或核对所需的业务标识时，才进行展示，并使用面向用户的名称。不要把工号、订单号等业务编号机械地视为后端技术 ID。

## 交互状态

对具有明确容器的交互控件建立清晰的状态层级：静止态最浅，悬停态加深，持续选中态进一步强调；存在按下态时，其强调程度不得弱于选中态。使用短促、平滑的颜色过渡连接状态。

按钮焦点只响应键盘触发的 `:focus-visible`：保持填充色和文字色不变，清除 Ant Design 与浏览器默认的 `outline` 和 `box-shadow`，普通按钮只将既有边框改为更深的项目主强调色，危险按钮改为更深的危险色；不要让边框直接跟随深色正文文字而变成黑色或深灰色。`text` 和 `link` 按钮静止态保留透明边框，避免焦点时改变尺寸。将覆盖放在项目的 Ant Design 全局样式层，使用项目根容器和 `.ant-btn:focus-visible` 提高选择器优先级，仅在必要时限定使用 `!important`；不要叠加新的焦点环，也不要移除键盘焦点反馈。鼠标点击获得焦点时不保留焦点反馈。

将输入类控件与按钮统一为单层焦点边框。`Input`、`TextArea`、`InputNumber`、`Select`、日期选择器和分页跳转输入在鼠标或键盘聚焦时，都保持填充色、文字色和尺寸不变，清除默认 `outline`、`box-shadow` 和内描边，仅将既有 1px 边框改为更深的项目主强调色；错误、警告等校验状态继续使用对应状态色。复合控件通过 focused class 或 `:focus-within` 修改最外层可见容器，不要同时装饰内部 input。

## 表格

### 查询

表格筛选不提供“查询”按钮。任一筛选条件变化后，固定防抖 `200ms` 自动查询并回到第一页。提供“重置”按钮；重置全部筛选条件、回到第一页并立即查询，不等待防抖，也不要随后重复发起一次防抖查询。

### 行操作

保持表格操作列轻量。所有操作只显示文字，禁止附带图标，也不要使用实心或常驻背景按钮。在当前页面内执行命令时，使用 Ant Design `Button type="text"` 呈现静止态无背景的主强调色文字；删除、停用、下线等危险命令增加 `danger`，呈现静止态无背景的红色文字；凡导航到其他页面，无论同页签还是新页签，都使用路由 `Link` 或 `<a>` 的真实链接语义并呈现项目链接色。不要为规避 Ant Design 默认样式而改用语义不符的原生按钮。悬停和按下仍遵循交互状态规则。

## 选择器

### 完整选项的本地搜索

当后端一次性返回完整且数量可控的业务选项时，即使选项不多，也要让 Ant Design `Select` 支持按可见名称进行前端本地搜索；不要为此请求后端，也不要扩展拼音匹配。
